\chapter{Reproducibility}\label{app:repro}

This appendix says how to run the whole study again, from an empty folder to the PDFs.

The code, the settings, the results summaries, the frozen pre-registration, its deviation log
and this report are kept in one private repository, available from the authors on request. The
EEG data are public: they are downloaded from figshare~\cite{wang2026figshare}, where Wang et
al.\ published them under the CC~BY~4.0 licence. Table~\ref{tab:repro-commands} lists the
steps, run from the top folder of the repository; its runbook (\code{docs/RUNBOOK.md}) says
what each one should print.


Four things keep the numbers the same on a re-run. \textbf{Seeds} for folds, draws, training
and the bootstrap are fixed in the settings files (Appendix~\ref{app:hyper}). \textbf{The window
cache} has a manifest (channels, sampling rate, window, exclusions, code version, a checksum per
file) that every later step checks before it runs. \textbf{Every result row} stores the git commit
that made it and hashes of its settings and of the data manifest. \textbf{Git tags} mark fixed
points: \code{setup-v1}, \code{prereg-v1} and \code{prereg-rq5-v1} (plans frozen before the main
results) and \code{results-v1}; \code{demo-v1} and \code{submission-v1} will follow. Their dates
are git's own, not those of an independent registry (Appendix~\ref{app:prereg}). No result in
this report is typed by hand: a script writes each one as a LaTeX macro from the results
summaries. Classical methods give identical numbers on a re-run; networks trained on a GPU
(Section~\ref{sec:tools}) can differ slightly.

\chapter{Hyperparameters}\label{app:hyper}

This appendix lists every setting of every model. All of them were fixed in the
pre-registration before the main results, except the transfer settings, which were chosen once,
by a rule written in advance, on two development patients (\code{sub-01} and \code{sub-03}) and
never on their test runs; the other patients served as sources as in the main study, their
test runs included. The settings live in \code{configs/\allowbreak models/} and \code{configs/\allowbreak protocol.yaml}.

The target weight says how much one of the new patient's windows counts against one window of
another patient. On the development patients the three candidate weights for re-centred TS+LR
scored between \pct{\rqTwoHparamRctTslrMeanMin} and \pct{\rqTwoHparamRctTslrMeanMax}, all near
the 33.3\,\% of guessing, so the choice made little difference there. The highest-scoring
weight, one, is also the least adaptive: each of the new patient's windows then counts as much
as one of the other patients' thousands of windows.

\chapter{Pre-Registration and Deviations}\label{app:prereg}

This appendix gives the hypotheses we wrote down before the main results, what came of each, and
every change made to the plan after it was frozen.

\section{The hypotheses}

A pre-registration is a plan written and frozen before the data are analysed. It fixes the
questions, the methods and the tests, so that the results cannot steer the analysis. Ours was
frozen in the project's git repository under the tag \code{prereg-v1}, on a commit dated
3 October 2026; the tag itself was made on 8 October. These are git's own dates, written by
whoever makes the commit and the tag: the plan was not registered with an independent registry,
and it is available, with its deviation log, from the authors on request. The separate
depression study was frozen as \code{prereg-rq5-v1} before any of its data were downloaded. Table~\ref{tab:app-hypotheses}
lists the hypotheses. ``Supported'' means the test passed its pre-set bar. ``Contrary'' is
possible only for a two-sided test whose effect is significant in the other direction.
``Inconclusive'' means neither, which is not evidence that the opposite is true; a one-sided
test whose effect points the other way is inconclusive. $W$ is the sum of positive ranks for a
one-sided test and the smaller rank sum for a two-sided one, and $r$ the rank-biserial
correlation.

\section{What it plays}

The demonstrator replays the last two runs of patient \demoSubject{}: \demoTrials{} whole trials
that the model never trained on, at their real speed. The model is an EEGNet trained on that
patient's first two runs. It reads each 4\,s window and says whether the patient was imagining a
movement or resting. On these held-out windows it was right \pct{\demoMoveRestAcc} of the time
for move or rest (balanced accuracy). When it reads a movement it also guesses which one, hand
or sixth finger; that guess is right \pct{\demoHandFingerAcc} of the time, where guessing gets
50\,\%. The EEG is a recording, replayed; no headset is connected. The hand is a drawing; no
physical finger moves. The demonstrator does not read thoughts, and it is not a medical device.

\section{The screen, left to right}

\begin{enumerate}
\item \textbf{The patient is told.} The instruction on the patient's screen at that moment:
      rest, get ready, or imagine moving the hand or the sixth finger.
\item \textbf{Their brain signal.} Three of the 40 sensors, over the part of the brain that moves
      the hands, drawn as the signal arrives.
\item \textbf{The model reads.} ``Move'' or ``Rest'', marked right or wrong against the
      instruction; how sure the model is; its guess of hand or finger; and a drawn hand whose
      robotic sixth finger bends when the model reads a movement. Below it are the running
      score, where the decision was made and how long it took.
\end{enumerate}

A badge above the screen names where the model is running: ``Model running on the server'',
``Model running in this browser'' or ``Showing stored decisions''. The page chooses by itself.
It uses the server if one answers; otherwise it runs the same model inside the browser; if even
that fails, it replays the decisions the same model made earlier, and the badge says so.

\section{The controls}

\begin{itemize}
\item \textbf{Space} pauses and resumes. The \textbf{left} and \textbf{right arrow} keys go to
      the previous or the next trial. The speed buttons play at 1$\times$, 2$\times$ or 4$\times$.
\item \textbf{Per trial} reads the 4\,s after each instruction, as the study tests the model.
      \textbf{Continuous} reads every half second without knowing when instructions come, as a
      real device would; the finger then follows the command gate of Appendix~\ref{app:hyper}.
\item When a server is available, \textbf{On the server} and \textbf{In this browser} choose
      where the model runs.
\item Keys \textbf{1}, \textbf{2} and \textbf{3} pose the hand directly (rest, hand closed, sixth
      finger bent) to check the drawing. A banner then says that this is a manual test and not
      decoded EEG; \textbf{Esc} returns to the recording.
\end{itemize}

\section{Running it without the internet}

On a laptop with the repository, \code{npm -{}-prefix web run build} followed by
\code{npm -{}-prefix web run preview} serves the page at \url{http://localhost:4173}. It then
decodes in the browser with no outside connection. \code{make demo} starts the local streaming
server and the page together.
